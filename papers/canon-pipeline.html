Canon Pipeline Benchmarks — How the Best Turn a Raw Corpus into a Canon

Dawn Studio · 2026-11-22 · filed in full in the Dawn DB · 全文研究報告 · Full-text research report

Canon Pipeline Benchmarks — How the Best Turn a Raw Corpus into a Canon (and a Canon of Canons)

Summary

No single tradition does all 7 stages (0–6) well. The strongest composite is:

  • Stage 0 — Prepare the curator: Forte/Feynman's 12 Favorite Problems + Karpathy's schema file (CLAUDE.md/AGENTS.md) that turns a generic agent into “a disciplined wiki maintainer.” Write the rubric before ingesting anything.
  • Stage 1 — Total index: Karpathy's immutable raw/ + Locke's two-key index + Zep/Graphiti's non-lossy episode subgraph. Capture everything, edit nothing, give every item a permanent, content-addressed ID and a findable head-word.
  • Stage 2 — Summarise: Map-reduce / hierarchical summarization (cheap model per chunk at 10–20% compression, expensive model only for reduce) + the **Siku tiyao template** — every summary is also a critical evaluation, not just a précis.
  • Stage 3 — Distill: Forte's Progressive Summarization (bold → highlight → executive summary, ~10% of 10% each pass, only on revisit) + Generative Agents' reflection trigger (when accumulated importance crosses a threshold, synthesise higher-level insights with citations to the memories below them).
  • Stage 4 — Curate/select: A scored, multi-criteria gate with a written rejection ledger — Siku's cunmu 存目 (rejected-but-reviewed), Mem0's ADD / UPDATE / DELETE / NOOP reconciliation, and Wikipedia's Featured Article criteria + adversarial nomination review. Your four criteria (detailed, catchy/juicy, informational, educational) become 4 of ~7 scored axes; add provenance/authenticity, non-duplication/originality, and cross-corpus corroboration — the three criteria every historical canon actually used.
  • Stage 5 — Build the canon: Luhmann/Matuschak atomic, concept-oriented, densely linked notes + Milo's Maps of Content (MOCs) + Karpathy's wiki with index.md + log.md, organised by a small fixed taxonomy (Siku's 4 divisions / 44 subcategories) plus associative links, not by folder alone.
  • Stage 6 — Canon of canons: Repeat stages 2–4 on the canon itself, one level up: Siku did this literally (200-juan Zongmu Tiyao → 20-juan Jianming Mulu 簡明目錄, an abbreviated catalogue of the catalogue); Zep does it as community subgraphs with high-level summaries; Letta does it as core memory (a bounded, always-in-context essence distilled from archival memory). Rule: the canon-of-canons must be small enough to hold in one context / one sitting, and every entry must point down to its full canon entry, which points down to raw sources.

Confidence: high on the methods and criteria below — each is corroborated by ≥2 independent sources in the index (see Sources). Exact historical counts for Siku vary slightly by source (3,461 / 3,503 / 3,593 titles included) — reported as a range, not a single figure.

Findings

1. Personal Knowledge Management

1a. Tiago Forte — Building a Second Brain: CODE + Progressive Summarization + PARA

Method in brief. CODE is the lifecycle of every item: Capture → Organize → Distill → Express.

  • Capture: “keep what resonates.” Not everything — only what surprises, inspires, challenges, or is useful. The filter is pre-analytical (resonance), which makes capture sustainable.
  • Organize: PARA, by actionability, not topic. Projects (active, deadline), Areas (ongoing responsibilities), Resources (reference), Archives (inactive). Ask “which project will this help?” not “what is this about?”
  • Distill: Progressive Summarization (see below).
  • Express: turn notes into an output; value is measured by what comes out. Intermediate form: Intermediate Packets — small reusable chunks (a summary, a paragraph, a diagram) that big works are assembled from.

Sources: https://www.frankanaya.com/second-brain/ ; https://www.ideandigest.com/books/building-a-second-brain/ ; https://www.viableedge.com/blog/progressive-summarization

Progressive Summarization — the copyable core for Stages 2–3. Distill in layers, only when you revisit, so effort follows proven value; most notes never pass Layer 2, by design:

LayerActionCompression
1Save the original passage, with source100% of excerpt
2Bold the sentences that carry the point~10–20% of L1
3Highlight the best phrases within the bold~10–20% of L2
4Executive summary at the top, 3–5 bullets in your own wordsessence
5 (Express)Remix into your own output—

Each layer is roughly a tenth of the one before; a layered note can be read at any speed (skim L4, or drop to L1 for detail). Forte calls the mechanism stigmergy: each pass leaves marks that make the next pass cheaper.

Stage-0 tool — 12 Favorite Problems (borrowed from Richard Feynman): keep ~12 open questions constantly in mind; test every new item against them (“does this help answer one?”). In BASB teaching they serve as “a filter for what to capture… and a north star” for projects. Source: https://www.goodreads.com/author/show/17177938.Tiago_Forte/blog?page=12

Selection/promotion criteria: resonance at capture; proven reuse for promotion (a note earns the next layer only by being revisited/used); actionability for filing. Copyable: (0) write your 12 questions first; (2–3) never summarise fully in one pass — do cheap bold-equivalent first pass on everything, expensive own-words summary only for survivors; keep all layers in the same record so distillation is lossless/reversible.

1b. Niklas Luhmann — Zettelkasten (slip-box)

Method. ~90,000 paper slips (Bielefeld archive), 1950s–1990s; credited for 70+ books, 400+ articles. Pipeline: Fleeting notes (capture, process within 24–48h, then discard) → Literature notes (what a source says, in your own words, with citation) → Permanent notes (one atomic idea, in your own words, linked, filed by branching address).

  • Atomicity: one idea/claim per slip, fits a half-sheet; if you can't state it in a few sentences you haven't understood it.
  • Autonomy: each slip understandable without its source or neighbours.
  • Branching address, not sequential numbering: a continuation of 1 is 1a, a comment on 1a is 1a1, the next step after 1a is 1b (e.g. 21/3d26g53). New notes insert between old ones forever without renumbering — growth is internal, no preconceived scheme.
  • Two link types: (i) sequence/branch proximity, (ii) explicit cross-references at the bottom of a slip to distant slips. A keyword register/index lists only a few central entry-point slips per keyword — the index is deliberately sparse; you enter there and follow links.
  • He described the box as a Gesprächspartner (conversation partner): browsing links surfaces outlines and connections he hadn't planned.

Sources: https://ivgraph.com/journal/zettelkasten/ ; https://www.fastcompany.com/90535318/this-simple-but-powerful-analog-method-will-rocket-your-productivity?partner=rss&amp;utm_source=rss&amp;utm_medium=feed&amp;utm_campaign=rss+fastcompany&amp;utm_content=rss

Selection/promotion criteria: fleeting → permanent only if it states a reusable idea in your own words and can be linked to ≥1 existing note; value = link density, not count. Copyable: (1) permanent IDs that allow insertion (or UUID + explicit sequence links); (3) split every summary into atomic claim-notes before curating — curate claims, not documents; (5) maintain a sparse entry-point index (few hubs per topic), not an exhaustive tag list.

1c. Andy Matuschak — Evergreen Notes

Method. “Evergreen notes are written and organized to evolve, contribute, and accumulate over time, across projects.” Five principles (primary site):

  1. Atomic — one concept per note; “capture the entirety of that thing” but nothing else.
  2. Concept-oriented — organised/name​d around the concept, not the source/book/author/date.
  3. Densely linked — links are the substrate, not an afterthought.
  4. Prefer associative ontologies to hierarchical taxonomies — flat namespace + links beats deep folders.
  5. Write for yourself by default, disregarding audience — lowers the cost of honest thinking.

Signature move: titles as declarative claims / APIs — not Spaced Repetition but Spaced repetition can be used to develop conceptual understanding. A claim-title can be agreed/disagreed with, linked precisely, and scanned in an index without opening the note. Notes are continually revised (add counterarguments, new evidence) rather than frozen.

Sources: https://notes.andymatuschak.org/zNUaiGAXp21eorsER1Jm9yU ; https://fabric.so/learn/evergreen-notes

Copyable: (5) canon entries are concept-pages titled by their claim, not conversation-pages titled by date/source; (6) canon-of-canons entries are the highest-level claims, each linking down to the concept-pages that support/contest them. Add a “revised-on” date — canon entries are evergreen, not final.

1d. John Locke — Indexing the Commonplace Book (1685/1706)

Problem: you don't know in advance which headings you'll need or how much room each needs; a full alphabetical index wastes pages and needs rewriting. Method. Reserve only the first two facing pages as the index. Grid: rows = first letter of the head-word, columns = the five vowels. A heading lives in the cell = first letter + first vowel that follows it (e.g. Epistola → E.i; impossible combos are omitted — Q gets only Q.u, ~100 cells total). Workflow: (1) find a proper head — “some important and essential word to the matter in hand”; (2) look up its cell; (3) if empty, take the first blank page, write the head large in the margin, copy the passage, write that page number in the cell; if occupied, append on that page (or the next blank page, adding its number and a back-pointer from the filled page). Headings are created on first need; pages are allocated in order of first need; any heading is found in exactly two steps.

Sources: https://fs.blog/john-locke-common-place-book/ ; https://templacity.com/remarkable/commonplace-book/

Copyable: (1) this is the cheapest possible total index for Stage 1: a fixed-size, two-key hash (first-letter + first-vowel = the 17th-century equivalent of a hash bucket) with append-only allocation and no pre-planning. Modern form: every raw item gets (a) one essential head-word/claim, (b) a bucket key derived mechanically from it, (c) an append-only page/ID. Retrieval in O(1) steps, zero taxonomy debate at ingest.

1e. Nick Milo — Linking Your Thinking (LYT) / Maps of Content (Obsidian community)

Method. Notes connect by meaning (wikilinks + automatic backlinks), not folders. When a cluster grows unwieldy, create a Map of Content (MOC): a single note that is mostly curated, annotated links grouped under subheadings reflecting how you actually think about the topic.

  • Trigger (“mental squeeze point”): make a MOC when you feel strain navigating — practically, ~8–10+ notes on a subject and you keep searching for them. Not upfront.
  • MOC creation: Dump → Lump → Jump — collect links, group + annotate them, revisit/refine.
  • Home note = a MOC of MOCs (single top entry point). ACE folders if folders are needed: Atlas (space/knowledge), Calendar (time), Efforts (importance/action), plus + inbox, x extras.
  • ARC gap: most people over-invest in Adding and skip Relating (contextualising, connecting, challenging) before Creating.
  • A MOC is curated, not automatic (“the judgment is the value”), non-destructive (a note can sit in 5 MOCs; deleting a MOC touches nothing), and heterarchical (MOCs link peer-to-peer).

Sources: https://danholloran.me/posts/linking-your-thinking-in-obsidian-how-mocs-replace-folders ; https://github.com/maxpetretta/zettelclaw/blob/HEAD/docs/knowledge-management-methodologies.md

Copyable: (5) the canon's table of contents should be MOCs, not a folder tree — one canon item can appear in several MOCs; (6) the canon-of-canons is the Home note: a MOC of MOCs. Create MOCs only at squeeze points, in Dump→Lump→Jump passes.

2. Historical Canon Formation at Civilisation Scale

2a. Buddhist Councils — Saṅgīti (結集, “reciting together”)

Method. Councils convened to compile, verify and freeze an oral corpus before distortion set in. First Council (traditionally 3 months after the Buddha's death, Sattapanni Cave, Rājagṛha, under Mahākassapa, 500 arahants): Upāli recited the Vinaya (discipline) from memory, Ānanda recited the Suttas; after each recitation the assembly confirmed correctness and re-chanted in unison; a text was compiled only on unanimous acceptance. Agreement formula: these are the authentic words; nothing is to be added or removed. Later councils repeated the entire corpus word-for-word in concert, settled disputes, and purged misinterpretations (Second: 700 monks, Vaiśālī, ~100 years later, rejected liberal reinterpretations of precepts; Third: under Aśoka at Pāṭaliputra, under Moggaliputta Tissa, cleared confusion and compiled the Abhidhamma). Resulting structure — Tipiṭaka, “three baskets”: Vinaya / Suttanta / Abhidhamma. The corpus stayed oral until the Fourth Council era; saṅgīti itself is defined in the scholarly literature as recitation “for collection, compilation, classification, verification, authentication, approval and memorization.”

Sources: https://www.vridhamma.org/The-Six-Councils ; https://atbu.org/files/Sangiti.pdf ; https://www.tibetanbuddhistencyclopedia.com/en/wiki/Buddhist_Councils

Selection/promotion criteria: (i) traceable to the authoritative source (recited by the direct custodian — Ānanda/Upāli); (ii) unanimous cross-verification by independent rememberers; (iii) coherence with the already-accepted Dhamma/Vinaya; (iv) freeze rule after acceptance. Copyable: (4) promotion requires independent corroboration — an item enters the canon only if ≥2 independent sources/extractors produce it, or one extractor + a verifier pass agrees verbatim on the claim; disagreements go to a council-style adjudication queue, not silently in. (5) classify into a tiny number of top “baskets” by function (rules / discourses / analysis) before any finer taxonomy.

2b. Siku Quanshu 四庫全書 + Zongmu Tiyao 總目提要 — the strongest historical model for this pipeline

Scale & workflow (1772/73–1782, Qianlong). Empire-wide requisition: provincial officials and private owners sent books to Beijing (after an edict promising return and non-persecution, 4–5,000 arrived within months). Editorial board of 361+ scholars (chief editors Ji Yun 紀昀 and Lu Xixiong), ~3,826 copyists. Of ~10,680 titles catalogued, ~3,461–3,593 were copied in full into the Quanshu (36,381 volumes, ~79,337 juan, ~997M characters, 7 manuscript sets); **~6,793 were listed by title only (cunmu 存目); ~3,000 anti-Manchu titles were destroyed — the project's preservation and its censorship are inseparable, and the second is a warning (see below). Classification: the traditional four divisions (sibu) — 經 jing Classics, 史 shi History, 子 zi Masters, 集 ji Belles-lettres — refined into 44 subcategories**, chronological order within each; every category/subcategory opens with a preface (xu) synthesising its field.

Sources: https://en.wikipedia.org/wiki/Siku_Quanshu ; http://www.chinaknowledge.de/Literature/Science/sikuquanshu.html

**The Tiyao method — copy this template verbatim for Stage 2/4.** For every book — included and rejected — the compilers wrote a tiyao 提要 (abstract-review), 200 juan in total. A tiyao is not a neutral summary. From the examples and secondary analysis, each entry does, in order:

  1. Bibliographic facts: title, juan count, author (with biography/office), dynasty, edition/transmission history.
  2. Contents précis: what the book actually covers/argues, its structure and method.
  3. Source & authenticity audit: sources used; anachronism/forgery detection — vocabulary, institutions, or citations from the wrong period; cross-checks against dynastic bibliographies and citation chains; prose-style comparison.
  4. Balanced critical verdict: strengths and weaknesses named specifically (e.g. of one biji: over-trusts a forged text here, lightly trusts fiction there — but these demonstrations are “carefully grounded”; verdict formula xia bu yan yu, yu bu yan xia 瑕不掩瑜 — “flaws do not eclipse merits, merits do not eclipse flaws”); placement relative to predecessors (“in modern commentaries, second tier”).
  5. Disposition: copied in full (著錄) / listed by title only (存目) / rejected — with the reason stated in the review itself.

Sources: https://sixlines.day/en/blog/emperors-library-319-rejected ; https://sixlines.day/en/blog/imperial-catalog-yijing ; worked tiyao translations at https://ask.bunkankun.org/KR1/KR1b/KR1b0055

Explicit inclusion criteria (from the project's stated rules): works instructing in proper moral behaviour; commentaries, textual criticism and Hundred-Schools works of “practical value”; prose/poetry of famous scholars. Exclusion patterns reconstructed from the cunmu reviews (no formal rubric — continuous prose, but consistent clusters): fraudulent attribution/forgery; derivative scholarship (restates earlier scholars better expressed elsewhere, adds nothing original — the largest rejection category); flashy/meaningless style over solid scholarship; unofficial/how-to ephemera; authors of questionable conduct; (and, politically) anti-Manchu content. Source: http://xirugu.com/CHI500/TradCat/Sikuquanshu.html ; https://sixlines.day/en/blog/emperors-library-319-rejected

The canon-of-canons move: alongside the 200-juan Zongmu Tiyao they compiled the ***Siku Quanshu Jianming Mulu 簡明目錄, a 20-juan* abbreviated catalogue** “to make orientation in this vast compendium easier” — a distillation of the catalogue itself, one-tenth its size. Source: http://www.chinaknowledge.de/Literature/Science/sikuquanshu.html

Copyable: (1) requisition = total capture with a return/no-penalty promise (removes contributors' fear of submitting); (2) **one tiyao per item, summary + audit + verdict + disposition in a fixed template; (4) two-tier outcome, never binary delete**: full inclusion vs. cunmu (title + review preserved, full text not promoted) — your rejection ledger is a deliverable and proves the canon was selected, not just accumulated; derivative-ness (“said better elsewhere, adds nothing”) as a first-class rejection reason; (6) publish a Jianming Mulu-style short catalogue of your own catalogue. Warning to copy in reverse: Siku shows a canon-maker with a political exclusion criterion destroys ~3,000 titles and poisons trust in the rest — keep exclusion criteria content-based, written, and applied in the open review text.

2c. Biblical Canon

Method. No single council invented the list; centuries of use → regional councils (Hippo 393, Carthage 397/419) ratified a consensus already formed; Athanasius's 367 festal letter first lists exactly the 27 NT books. The process was recognition, not invention — and it was slow, contested at the edges (Hebrews, 2 Peter, Revelation long disputed), and never fully uniform across traditions (Catholic/Orthodox canons include the Deuterocanon).

Criteria (reconstructed from early-church practice; no formal list was published at the time):

  • Apostolicity — by an apostle or a close associate conveying apostolic teaching (Mark via Peter, Luke via Paul); ≤1 person removed from an eyewitness.
  • Orthodoxy — consistent with the regula fidei, the rule of faith already handed down.
  • Catholicity — widely read/used across geographically separate churches; a book known to only one region/sect could not qualify, however edifying.
  • Antiquity — from the apostolic age; later works rejected on recency alone (e.g. Shepherd of Hermas in the Muratorian Fragment).
  • Plus continuous liturgical/teaching use.

Sources: http://biblicaltraining.org/library/bible-canonicity ; https://www.brnow.org/opinions/voices-opinion/Is-the-Bible-limited-to-66-books/

Copyable: these map 1:1 onto modern provenance scoring — apostolicity = proximity to primary source (first-hand account > retelling > commentary); catholicity = independent uptake across separate clusters of your corpus (a claim/theme appearing in many independent conversations outranks one repeated inside a single thread); orthodoxy = consistency with the already-promoted canon (new items that contradict promoted items need adjudication, cf. Zep invalidation below); antiquity/proximity-in-time to the event described.

2d. Other canon processes worth one line each

  • Confucian Classics / Chinese bibliographic tradition: the sibu taxonomy itself was inherited from Han imperial-library cataloguing (Liu Xiang/Liu Xin's Qilüe) — i.e. Siku's Stage-5 taxonomy was a received schema refined, not invented; lesson: adopt an existing taxonomy and refine subcategories, don't design one from scratch.
  • Buddhist Chinese canon (大藏經) catalogues applied the same cunmu-like logic (authentic / doubtful / spurious 經錄 categories) — independent confirmation that a doubtful/spurious tier is a recurring best practice, not a Siku quirk.

3. Modern AI-Era Practice

3a. Andrej Karpathy — LLM Wiki / LLM Knowledge Bases (X post 2 Apr 2026; gist llm-wiki.md 4 Apr 2026)

Primary gist: https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f

Core idea: “Stop retrieving. Start compiling.” Instead of RAG re-reading raw documents at every query, the LLM compiles them once into a persistent, interlinked Markdown wiki and keeps it updated. Analogy: raw = source code, wiki = binary; “Obsidian is the IDE; the LLM is the programmer; the wiki is the codebase.” At posting, one topic wiki had reached ~100 articles / ~400,000 words, none written directly by Karpathy.

Three layers:

  1. raw/ — immutable. Papers, articles (via Obsidian Web Clipper, images saved locally — no link rot), repos, notes, data. Append-only; LLM reads, never modifies; ground truth you can re-compile from.
  2. wiki/ — LLM-owned. Source summaries, entity pages, concept pages, comparisons, overview; plus two navigation files: index.md (content catalogue, one line per page, updated on every ingest — the LLM reads this first) and log.md (append-only chronological ledger, fixed heading prefix so grep "^## \[" parses it).
  3. Schema — CLAUDE.md/AGENTS.md. Conventions, page templates, ingest/query/lint workflows. “The key configuration file” — it turns a generic chatbot into a disciplined wiki maintainer, and it co-evolves with use.

Three operations:

  • Ingest: read new source, discuss takeaways, write its summary page, then fan out: one source typically touches 10–15 wiki pages — update entity/concept pages, revise summaries, flag contradictions, strengthen cross-links; update index.md, append to log.md.
  • Query: read index.md first, then only needed pages; file good answers back into the wiki as new pages so explorations compound like sources.
  • Lint: periodic health-check — contradictions, stale claims, orphan pages, concepts mentioned but lacking a page, missing cross-references, data gaps to fill with a new source.

Sources: https://github.com/akitaonrails/ai-memory/blob/HEAD/docs/research-karpathy-llm-wiki.md ; https://dev.to/starmorph/how-to-build-karpathys-llm-wiki-the-complete-guide-to-ai-maintained-knowledge-bases-3dk3 ; https://codersera.com/blog/karpathy-llm-knowledge-base-second-brain/

Copyable: this is Stages 0–1–5 as a file layout. Adopt verbatim: immutable raw, schema-as-curator-training, ingest fan-out count (10–15 touches) as a quality check, index+log as separate artefacts, lint as a scheduled Stage-4.5, and file-back of good query answers.

3b. Memory architectures for AI agents — how machines decide what to keep, summarise, promote

Letta (formerly MemGPT) — OS-style tiered, self-editing memory.

TierAnalogueContentsRule
Core memoryRAM / cacheSmall, bounded, always in context; typed editable blocks (persona, human, task, project…) each with a character limit + description of when to editAgent edits it itself via tool calls (core_memory_append/replace); a block near its limit must be summarised
Recall memoryDisk logFull conversation history, append-only, searchableAutomatic; nothing is decided here
Archival memoryCold storageEffectively unlimited facts/passages in a vector store, queried on demandAgent explicitly inserts/searches

Mechanics that matter: memory-pressure signals — when context fills, the agent is prompted to summarise/evict; overflow evicts oldest in-context messages (they persist in recall — demotion, not deletion) and injects a summary of them; sleep-time agents (2025 addition) run in the background, off the critical path, processing transcripts to consolidate, rethink and reorganise core blocks and archival records. Eviction scoring recommended over naive FIFO/LRU: access frequency × recency. Sources: https://github.com/nirdiamant/agent_memory_techniques/blob/HEAD/all_techniques/26_letta_memgpt_patterns/README.md

Mem0 — extraction + reconciliation loop. Two LLM passes per message pair: (1) Extraction — using the conversation summary + recent messages, extract candidate salient facts; (2) Update — retrieve similar existing memories, and an LLM decides per candidate: ADD (net-new) / UPDATE (same entity, changed value) / DELETE (contradicted) / NOOP (already known). Result: memory stays ~1,800 tokens/conversation vs ~26,000 for full-history replay (Mem0 paper figures, as reported). Graph variant stores entity–relation–entity triplets. Sources: https://memo.d.foundation/breakdown/mem0 ; https://dev.to/mukesh_13/mem0-vs-zep-vs-langchain-memory-vs-letta-which-one-actually-remembers-2j47

Zep / Graphiti — temporal knowledge graph, non-lossy. Three subgraphs mirroring the whole pipeline in miniature:

  • Episode subgraph — raw messages/text/JSON stored non-lossily, with reference timestamps (Stage 1).
  • Semantic entity subgraph — entities extracted, resolved/deduplicated against existing entities; fact-edges between them, each edge carrying the episodes that support it (Stages 2–3).
  • Community subgraph — clusters of strongly-connected entities with high-level summaries (Stage 6 in embryo).

Facts are bi-temporal (valid-time vs ingestion-time; valid_at/invalid_at + created_at/expired_at): when a new fact contradicts an old edge, the LLM sets the old edge's t_invalid — invalidate, never delete — preserving an audit trail / point-in-time truth. Retrieval fuses semantic + BM25 + graph distance, reranked. Source: https://arxiv.org/pdf/2501.13956 (Zep paper, arXiv:2501.13956)

Generative Agents (Park et al., Stanford/Google, UIST 2023) — the scoring formula. Every memory is scored at retrieval on three normalised (0–1, equally weighted) components: Recency (exponential decay, 0.995/hour since last access) + Importance (LLM-rated 1–10 at creation: mundane=1, poignant=10) + Relevance (embedding cosine to current situation). Reflection trigger: when the sum of importance scores of recent events exceeds 150, the agent takes its 100 most recent memories, generates salient questions, retrieves evidence, and writes higher-level insights citing the memories they rest on — reflections re-enter the stream, forming a reflection tree (raw observations = leaves, abstractions = higher nodes). Source: arXiv:2304.03442, via https://github.com/alexisolson/somnigraph/blob/HEAD/research/sources/generative-agents.md

Copyable (Stage 3–4 promotion engine, combined): score every distilled item promotion = recency × frequency-of-reuse + importance (LLM-rated 1–10 at summarise time) + relevance-to-12-problems; run Mem0's 4-way reconciliation against the existing canon on every ingest (this single step prevents canon bloat/contradiction); use Zep-style invalidation (superseded canon items are marked superseded-with-date + successor link, never deleted); trigger a reflection/distillation run by accumulated importance, not by calendar.

3c. Production pipelines for summarising/distilling large conversation archives

Map-reduce / hierarchical summarization (the standard production shape):

  1. Chunk semantically (split on topic shift, not fixed characters), 4,000–8,000 tokens/chunk, overlap for flowing transcripts, none for cleanly sectioned docs.
  2. Map (parallel, cheap/fast model): same prompt per chunk, compress to 10–20% (300–500 words/chunk is a typical spec), preserving all key facts, names, numbers, conclusions, relationships. Compressing to 3–5% at map stage loses detail the reduce stage can never recover; 30–50% leaves reduce over-length.
  3. Reduce (expensive/high-reasoning model): group summaries (e.g. 10 groups of 10) and summarise recursively until one synthesis remains; hierarchical levels preserve structure.
  4. Refine (alternative/complement): sequentially fold each chunk into a running summary — better narrative/logical continuity, slower.

Model routing rule: cheap model for the 90% map volume, frontier model for the final 10% synthesis. Sources: https://www.adaptiverecall.com/ai-summarization/map-reduce-summarization.php

Incremental variant (for a corpus that keeps growing): don't re-read everything each run. MAP extracts a structured record per new/changed conversation only; REDUCE folds new extracts into a bounded durable profile; a coverage gate skips REDUCE if MAP coverage is below threshold; idempotency via a generation hash (no change → no-op); long conversations windowed, never truncated. Source: https://mwylot.net/portfolio/incremental-mapreduce-insight-pipeline/

From chat/support logs to a curated KB — two concrete production patterns:

  • AI Knowledge Assist (contact-centre, peer-reviewed system): extract QA pairs from historical agent–customer conversations with a fine-tuned lightweight LLM (>90% extraction accuracy across 20 companies reported) → cluster similar QA pairs → construct one representative QA per cluster → human knowledge-manager reviews before insertion. Deduplication is the curation: 1,000 near-identical conversations become 1 canonical answer.

Source: https://arxiv.org/pdf/2510.08149

  • Curation-as-build-system (tickets/logs → versioned dataset): every record gets a content-addressed ID (hash of canonical form — exact duplicates collapse automatically); every pipeline stage is a pure function emitting a manifest (kept IDs + code/parameter hash); every dropped record goes to an append-only drop ledger with a reason — “a count of drops grouped by source and reason is the pipeline's best health report.” Cheapest quality filter first: ticket metadata (resolved? not reopened? satisfaction above threshold? final answer length) before any LLM call. Order matters: redact PII → deduplicate → split/select, so near-dupes differing only in an email still collapse. LIMA result cited throughout this literature: ~1,000 carefully curated examples beat tens of thousands of raw ones.

Sources: https://www.aicassindra.com/blogs/slm/training_data_curation.html

Copyable: Stage 2 = map-reduce with the 10–20% rule and two-tier model routing; Stage 4 = cluster-then-pick-representative (never promote two items covering the same claim — pick the best exemplar, cunmu the rest with a pointer to the winner); metadata pre-filter before spending LLM tokens; drop ledger from day one.

4. Editorial Curation Standards

4a. Wikipedia — Featured Article (FA) criteria + FAC process

Criteria (verbatim structure, https://en.wikipedia.org/wiki/Wikipedia:Featured_article_criteria): a featured article “exemplifies Wikipedia's very best work” and is:

  1. Well-written — prose engaging and of professional standard;
  2. Comprehensive — neglects no major facts/details, places subject in context;
  3. Well-researched — thorough, representative survey of the relevant literature; claims verifiable against high-quality reliable sources, inline citations where appropriate;
  4. Neutral — views fairly, without bias;
  5. Stable — not subject to ongoing edit wars / day-to-day churn;
  6. Copyright-compliant, no plagiarism/close paraphrasing.

Plus form criteria: a concise lead that summarises the whole article (a built-in canon-of-canons layer per article), appropriate hierarchical structure, consistent citations, suitable media, and length discipline — “stays focused… without unnecessary detail (summary style).” Below FA sits a graded ladder (A / Good Article / B / C / Start / Stub) — quality is a scale with named rungs, not pass/fail.

Process (FAC): optional peer review first → nomination (nominator must know the subject/sources and answer objections) → open review where actionable objections outweigh declarations of support (“the main thrust is to generate and resolve critical comments… resolution is given considerably more weight than declarations of support”) → coordinators (not a vote count) judge whether consensus that the criteria are met exists → promote, or archive with objections unresolved; archived nominations must fix issues before re-nominating. FA status can later be reviewed and removed (FAR). Source: https://en.wikipedia.org/wiki/Wikipedia:Featured_article_candidates

Copyable: adopt the ladder (e.g. Stub → Listed → Curated → Canon → Canon-of-Canons) with published criteria per rung; make promotion an objection-resolution process, not a popularity vote — a single unresolved factual/provenance objection blocks promotion regardless of support; require every canon entry to carry its own “lead” (2–3-sentence essence) — those leads, concatenated, are the first draft of Stage 6.

4b. Anthologies & “best of” readers — Norton as the worked example

Selection criteria stated by Nina Baym, general editor, Norton Anthology of American Literature: contents emerge from “extensive consultations among the editors, all experienced teachers,” plus “detailed responses from hundreds of instructors,” using “many measures of selection: aesthetic judgment, influence on the development of a [national literary] tradition, cultural impact of specific works, artistic innovation, and more.” Explicitly rejected: “pure literary value” as the sole criterion (“literary value is a moving target”). New editions both add and subtract — canon expansion is not addition-only. Source: https://www.chronicle.com/article/anthologies-serve-a-useful-purpose/

Process under a hard size budget (Norton Anthology of Theory and Criticism): when the typeset book came in ~500 pages over, each of 6 editors nominated candidates to cut, then the group debated as a group for two weeks — lists, passionate argument, “intellectual horse-trading” — cutting 21 thinkers entirely and trimming 3 more; the crisis became “an impromptu seminar on which figures are absolutely essential.” Norton production facts: 5+ years for a new anthology, ~2 years per new edition, scholar-editors + headnotes/annotations as part of the value (an anthology entry = text + framing apparatus, not text alone). Sources: https://www.chronicle.com/article/making-the-cut/ ; https://nortonlearningblog.com/2026/05/the-making-of-a-norton-anthology-with-editor-marian-johnson/

Copyable: (4) score on multiple incommensurable measures (your detailed/catchy/informational/educational + influence-within-corpus + innovation/first-statement-of-an-idea) and let a human/editorial pass resolve conflicts — don't collapse to one number; (5) every canon entry ships with a headnote (why it's here, what to notice, what it connects to) — the Siku tiyao verdict paragraph is a headnote; (6) enforce a hard size budget for the canon-of-canons and run a Norton-style forced-cut round: if it must shrink by 20%, what goes? What survives a forced cut is the essence.

6. Recommended Upgraded Pipeline (merged, with provenance per element)

Stage 0 — Prepare the curator [Karpathy schema + Forte/Feynman + Siku fanli]

  1. Write SCHEMA.md before touching data: mission, the 12 Favorite Problems/questions this canon must answer, the §4c rubric (7 axes, 1–5), the tiyao template, disposition codes (CANON / CUNMU / SUPERSEDED / REJECT-FORGED-DERIVATIVE-DUP), page templates, naming (claim-titles).
  2. Calibrate: curator (human + LLM) independently score the same 20 sample items; reconcile disagreements into schema examples (Wikipedia mentor/peer-review step). Freeze schema v1; version all later changes in log.md.

Stage 1 — Total index, unfiltered capture [Karpathy raw + Locke + Zep episodes + Siku requisition]

  1. Ingest everything into immutable raw/; never edit/delete; convert to Markdown/text, save assets locally (no link rot).
  2. Each item: content-hash ID, source, date, participants, metadata (resolved/rating/length where available). Append one line to log.md.
  3. Locke index: assign each item one essential head-word/claim; bucket = mechanical key from it; build the two-step index (index-raw.md). No taxonomy decisions, no filtering at this stage — filtering here is how corpora silently lose their best outliers.

**Stage 2 — Summarise (every item gets a tiyao)** [map-reduce + Siku tiyao + AI Knowledge Assist]

  1. Metadata pre-filter only for ordering (process high-signal items first), not exclusion.
  2. Map: cheap model, semantic chunks 4–8k tokens, 10–20% compression, preserving facts/names/numbers/quotes verbatim where juicy.
  3. Per item, emit a structured tiyao: bibliographic block → précis → atomic claims extracted as QA/claim pairs → authenticity/provenance note → strengths/weaknesses balance → provisional scores (§4c) → provisional disposition. Cluster near-duplicate claims across items as you go.

Stage 3 — Distill [Forte layers + Luhmann atomisation + Generative-Agents reflection]

  1. Split each tiyao's claims into atomic, own-words, claim-titled notes (one idea each, source-linked).
  2. Progressive passes: Pass A (all items) = bold-equivalent (mark the 10–20% core lines). Pass B (only items reused / scoring ≥ threshold) = highlight-equivalent. Pass C (only top items) = own-words executive summary.
  3. Reflection runs: when accumulated importance (Σ LLM importance 1–10) in a cluster crosses a threshold, synthesise a higher-level insight note citing the atomic notes beneath it; file it back into the corpus (Karpathy file-back).

Stage 4 — Curate / select [Siku gate + Mem0 + Wikipedia FAC + Norton multi-measure]

  1. For each candidate, run Mem0 reconciliation against the existing canon: ADD / UPDATE (merge, keep best detail) / DELETE-supersede / NOOP-duplicate. Cluster-winners only: within a duplicate cluster promote the single best exemplar (most detailed + juiciest telling), cunmu the rest with a pointer to the winner.
  2. Score on the 7-axis rubric; require minimums on provenance + non-derivative (historical canons' hard gates) and a high sum on your four (detailed/catchy/informational/educational).
  3. Adversarial review (FAC-style): a second pass (different model/persona or human) whose job is objections only — factual, provenance, duplication, contradiction. Unresolved objection blocks promotion regardless of score.
  4. Dispositions published: CANON (full entry) / CUNMU (title + tiyao + reason preserved, not promoted) / REJECT (forged, derivative-with-nothing-added, unverifiable — reason mandatory). This ledger is a deliverable.

Stage 5 — Build the canon [Karpathy wiki + Matuschak + Milo + Siku taxonomy]

  1. Canon lives in wiki/: one concept page per promoted claim-cluster, claim-titled, densely linked, with a headnote (= the tiyao verdict paragraph: why it's in, what to notice) and a 2–3-sentence lead at the top.
  2. Organise twice: (a) a small fixed taxonomy (adapt Siku: pick ~4 top divisions by function in your corpus, ≤~40 subcategories, chronological/source order inside), and (b) associative MOCs created only at squeeze points (Dump→Lump→Jump); a note may appear in many MOCs.
  3. Maintain index.md (updated every ingest) + log.md; run scheduled lint: contradictions (Zep-style: invalidate, don't delete — mark superseded + successor), orphans, missing links, stale claims.

Stage 6 — Canon of canons [Siku Jianming Mulu + Letta core + Wikipedia leads + Norton forced cut]

  1. Build only from Stage-5 leads/headnotes — never go back to raw at this stage (that guarantees true essence-of-essence, and makes the build cheap/auditable).
  2. Repeat Stages 2–4 at this level: summarise each canon division into one MOC-of-MOCs page; score/select with the same rubric, higher bar; the Home note = MOC of those pages.
  3. Enforce a hard size budget: target ~1/10 of the canon (Siku's ratio), small enough to read in one sitting / fit in one LLM context (Letta core-memory bound). If over budget, run Norton's forced-cut seminar: editors/models nominate cuts, debate as a group, cut ~20%, repeat until budget met.
  4. Every canon-of-canons entry links down: essence → canon entry → atomic notes → tiyao → raw item (hash ID). A reader can drill from essence to primary source in 4 clicks; an auditor can verify any essence-claim against raw.
  5. Version it (canon-of-canons v1, v2…); on each new ingest cycle, only changed canon entries re-enter Stage 6 (incremental map-reduce fold-forward).

Standing rules (all stages): immutable raw; invalidate-don't-delete; every promotion/demotion/rejection logged with a reason; effort follows proven reuse (don't gold-plate items nobody revisits); the schema is a living file — when a lint or council finds a recurring failure, fix the schema, not just the item.

Could not verify / open questions

  • Exact Siku inclusion count differs across sources (3,461 / 3,503 / 3,593 titles; catalogue totals 10,254–10,680). Reported as ranges; the method is unaffected.
  • Karpathy's gist was accessed via faithful secondary reproductions/summaries that quote it extensively and link the gist URL; the gist itself was not fetched line-by-line in the live browser in this run.
  • No primary Norton editorial manual is public; anthology criteria are from its general editors' published statements (Chronicle / Norton blog), not an internal rubric.
  • The mission did not specify corpus size, language mix, or whether promotion decisions are human, LLM, or hybrid — the recommended pipeline assumes hybrid (LLM map/score, adversarial second pass, human spot-audit) and scales from ~100 to ~100,000 items; thresholds (importance trigger 150, chunk sizes, 1/10 ratio) should be re-tuned to actual corpus size.
  • “Best of”/annual anthology series beyond Norton (e.g. Best American) were not separately deep-dived; their stated practice is consistent with Norton's multi-measure + guest-editor model, but that specific claim is not sourced above and should not be quoted as verified.
